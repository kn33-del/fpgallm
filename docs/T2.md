# T2 decode attention

`attn_unit` accepts one `attn_cmd_t` for one token and one decoder layer. The
baseline issues a fused QKV projection, applies split-half RoPE and requantizes
Q/K/V, commits the new K/V, loops through query heads, and writes the output
projection before raising `done`. Each score GEMM uses exactly `pos+1` positions,
so the decode path is causal. The top-level design currently specifies decode
with one query per head. Prefill with multiple queries is a separate operation.

## Addresses for integration

All offsets below are byte offsets in the indicated logical region. T4 maps
logical wide tile addresses to the physical HBM ports. The `attn_unit` base
parameters are configurable. The values in the table are RTL defaults for
integration with the host packer and T4.

| Parameter | Default | Contents |
| --- | --- | --- |
| `SCRATCH_BASE` | `0x00000000` in SCRATCH | QKV int16, QKV int8, scores, probabilities, concatenated heads. 17,408 bytes with the default dimensions. Reserve it for T2 while the command runs. |
| `KV_BASE` | `0x80000000` in HBM | Tiled key/value cache |
| `KV_SCALE_BASE` | `0x84000000` in HBM | Per-output-channel int32 GEMM multipliers for score and value GEMMs |
| `ROPE_BASE` | `0x85000000` in HBM | Packed table generated from the checkpoint configuration |

At `cmd.w_base`, pack the full tiled matrix `[Wq | Wk | Wv]` immediately followed
by tiled `Wo`. At `cmd.s_base`, place the corresponding Q/K/V multipliers followed
by the `Wo` multipliers. The default offsets for `Wo` and its scales are
6,291,456 and 12,288 bytes, respectively.

For `pair = layer*N_KV_HEADS + kv_head`, the matrix addresses are
`k_base = KV_BASE + pair*KV_BYTES` and `v_base = k_base + K_CACHE_BYTES`.
Each pair consists of tiled `K^T[HEAD_DIM, MAX_SEQ]` then
`V[MAX_SEQ, HEAD_DIM]`. Follow the package tile order with N tile outermost.
Each occupies 131,072 bytes at default dimensions. V's N-tile stride is
64 tiles (65,536 bytes), even when T1 reads a shorter prefix in each N tile.
`mm_cmd_t.b_row_stride` carries this physical stride. The zero default
preserves compact reads for the other GEMMs.

For a K/V append, T2 issues one request per KV head on `kv_wr`. Interpret
`req.base.off` as the logical slot tag `k_base + pos*HEAD_BYTES`. Each request
contains one row of four 256-bit beats by default. The first two beats
contain the rotated K vector and the next two hold V. T4 uses the token slot
and pair to scatter the bytes into their tiled addresses. Default cache tile
indices for lane `d` at position `p` are

- K tile `(p/32)*(HEAD_DIM/32) + d/32`, row `d%32`, column `p%32`.
- V tile `(d/32)*(MAX_SEQ/32) + p/32`, row `p%32`, column `d%32`.

T4 must pulse `kv_wr.done` after the append is visible to the wide B port.
Within each pair's scale region, place `MAX_SEQ` score multipliers followed by
`HEAD_DIM` value multipliers, with each vector padded to a whole T1 N tile.

## Numeric formats

These are the baseline formats for simulation and packing. A shared checkpoint
quantizer and bit-exact model reference remain integration work.

- The QKV projection writes signed int16 codes with seven fractional bits in
  units of the eventual int8 tensor code. For example, 448 represents 3.5.
  Values are rounded to nearest with ties away from zero and saturated to
  signed int8 after RoPE for Q/K and directly for V. Q uses one tensor scale
  within each group of four query heads. K and V can each use a scale per KV
  head. All lanes of a rotated head share its scale. The projection multiplier
  is `round(2^16 * 2^7 * x_scale * weight_scale / qkv_scale)` per output channel.
- RoPE pairs lane `i` with `i+HEAD_DIM/2`. Each table row contains
  `HEAD_DIM/2` cosines followed by that many sines as little-endian signed
  int16 with 15 fractional bits, lowest lane first. Position zero is an
  identity operation. Generate and load the table at `ROPE_BASE` before decode.

  ```sh
  python3 scripts/gen_t2_rope.py /path/to/config.json build/t2_rope.bin
  ```

  The coefficient generator implements the `default` and `llama3` formulas from
  [Transformers](https://github.com/huggingface/transformers/blob/main/src/transformers/modeling_rope_utils.py).
- Score GEMMs return signed int16 with eight fractional bits. The score
  multiplier folds in the attention scale `1/sqrt(HEAD_DIM)`. T1 applies
  `round(acc*multiplier/2^16)` by default, so the packer repeats
  `round(2^16 * 2^8 * q_scale * k_scale / sqrt(HEAD_DIM))` for each score
  channel in that KV group. A tensor scale here is the real value per int8
  unit.
- Softmax subtracts the maximum before exponentiating, interpolates a lookup
  table in Q16, and rounds each probability to a signed-compatible byte
  `0..127` representing `code/127`. Padding bytes are zero. This fixed scale
  rounds probabilities below half a quantization step to zero, which can
  discard diffuse attention on long prefixes. The value-GEMM multiplier is
  `round(2^16 * v_scale / (127 * head_out_scale))`. Use the same
  `head_out_scale` for all heads feeding `Wo`.
- `Wo` uses its usual per-output-channel multipliers. Its int16 output at
  `cmd.out_base` must use the residual stream's scale for the residual add.

## Simulation

Run `make test-t2` with Verilator. The testbench drives the T2 command,
matrix-command, and memory interfaces with backpressure and delayed commit.
It checks GQA command order and addresses, RoPE and saturation, K/V payloads,
softmax against integer and floating-point references, padding, and head concatenation.
It exercises position zero, a partial tile, and the maximum configured prefix.
The matrix and memory servers are modeled. Board integration depends on the
top-level arbiter, T4 cache manager, and checkpoint packer.
